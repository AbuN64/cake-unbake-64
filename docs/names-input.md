# Generic names input

The adapter extends the existing `symbols.py` name join; there is no separate names module.

`unbake names CATALOG --bindings LAYOUTS` reads schema-1 reader-neutral evidence and emits the existing Recipe structure move protocol. It does not edit the project. The result also includes changed alias symbol files, rewritten through Unbake’s existing `symbols.rename_lines` codec; compiler-owned `literals_<function>` names follow their owner. Functions match exact normalized version/address; type bindings require complete, identical size/member-offset/member-size/type signatures and independently established identity. Conflicts refuse the entire plan.

Pass the emitted moves to the existing `recipemaker.structure.build`, include `symbol_files` through Recipe’s existing `Files.put`/`Files.diff`, then apply the combined patch using `recipe apply PATCH` (which runs Unbake sync). There is no SYM decoder in Unbake, no new source rewriting engine, and no direct source edits.

Scoped field/parameter renames are unsupported by the current Recipe path and are listed explicitly as unmatched. The external reader is pinned in pyproject.toml to `https://github.com/AbuN64/psyq-sym-64@66fb01da73623d8e8a5fea4f342d7413cf6b8343`. The generic symbols adapter imports no reader-specific code.
