# Frozen contracts, revision 6

Frozen records and the public API of each module (revision 6). This file is shipped as `src/unbake/resources/CONTRACTS.md`; `tests/test_lint.py` reads its API table and its budgets: a module calls another only through the names in the other's row, and a public function is a row.

## Records (contracts.py)

`Json`, `digest(value) -> str`, `code_identity(*functions) -> str` (digest of the bytecode, constants and package callees they reach, once per process), `Origin`, `Finding`, `Refusal(*findings)`, `Host`, `Segment`, `VersionFacts`, `FileFacts`, `Project`, `Config`, `Version`, `UnitSpec`, `Snapshot` (config, commit, the captured `Tree`, the version records, overlays, digest), `Recipe`, `SourceView`, `NativeResult`, `Proof`, `Plan`, `Receipt`, `Submission`, `StageRecord`.

## Invariants

1. A `Refusal` always carries at least one `Finding`; every `Finding.key` is a key of `resources/data/keys.toml`.
2. `Finding.blocking=False` marks project debt. Debt never raises; it is returned and counted.
3. A `Proof` with `exact=False` has nonempty `missing` and `score < 1.0`; `exact=True` has `score == 1.0` and `symptoms == {}`. `land.not_exact` findings copy the `missing` strings and merge the proofs' symptoms.
4. Config values have no defaults. A missing or unknown key refuses with `config.schema` naming `file:dotted.path`. `"auto"` is an explicit host value for `resources.cores`/`resources.workers`; cores resolve to `len(os.sched_getaffinity(0))`; auto workers use the lesser of affinity and configured cores, bounded by the optional cap and available memory. System load does not reduce this capacity: the shared pool slots divide it between commands. `Origin.note` records the resolution. One exception: `resources.move_wait_s` is optional and reads 600 when absent, so existing host files keep loading. Likewise `resources.run_slice` (a systemd user slice such as `decomp.slice`; absent means none): `unbake-run` started outside that slice (per `/proc/self/cgroup`) re-execs itself under `systemd-run --user --scope --quiet --slice=<slice> -- <same argv>`, so make, gcc and the pools inherit it and the host's CPU split between users of the machine holds per slice weight, not per ssh session; a missing or refusing `systemd-run` runs the command in place with one stderr warning, never failing it.
Host tools used only by particular phases/commands are optional (`cpp`, `mips_as`, `mips_ld`, `mips_objcopy`, `mips_objdump`, `n64link`, `armips`). Config validates every supplied path as executable. A phase needing an omitted tool refuses with `native.missing_tool`, naming the tool and unit kind; no PATH fallback. Migration writes only supplied tools.

5. Every cache key is `contracts.digest(...)` of content (bytes digests, recipe digest, tool pins), never mtimes or reprs. A key that guards a producer holds `code_identity(producer)`, never a source file.
6. Unbake never writes Git state: no commit, no staging, no reset (read-only `rev-parse`, `ls-files`, `diff`, `show`, `log` only). Only `journal.apply` writes tracked project files, into the working tree, and only `land.drain`, `batch_data`, `blobs.apply_import` (`unbake blobs import`, under `store.exclusive(config, "structure")`, writing only `blobs.toml`) and `repo.setup` call it, `repo.setup` and  while they hold `store.exclusive(config, "structure")`, `batch_data` while it holds `store.exclusive(config, "land")` and then `store.shared(config, "structure")`, `land.drain` per claimed entry under `store.shared(config, "structure")` with the write alone serialised by `journal.lock`. `apply` stages every new content beside its target before taking `journal.lock`, then renames them all into place under it, and `layout.capture` reads under the shared side of that lock, so a capture sees the old file set or the new one. `apply` refuses a path whose current bytes differ from what the snapshot read (`Snapshot.reads`, seeded by the capture pins), journals the old bytes of every path (or absent) before writing, and returns the written paths for the caller to commit; the human output prints the exact `git add` and one-line `git commit -m`. Every other writer writes only untracked runtime files under `<project>/.unbake/` (inbox, ledger, stages, check.json), `local.mk`, view's content-keyed `build/views/<digest>/` materialisation (kept from revision 3), or the host cache, each by atomic create/rename or `O_APPEND`.
7. Only process.py starts processes, only pool.py creates worker processes, only effort.py, process.py and pool.py read rusage. Lint greps imports of `subprocess`, `multiprocessing`, `concurrent.futures`, `threading`, `os.fork`.
8. `view.all_versions` returns exactly the requested version keys.
9. Toolchain, assembler, linker, unit-kind and repository-file behaviour comes from resources; the strings `"gcc"`, `"ido"`, `"c"`, `"asm"`, `"data"`, `"resource"` appear only in resources and tests (lint).
10. Credit is state, not history: a name is matched in a version iff a file owns it as C (not behind a stand-in) and the last `make check` linked that version exact (`.unbake/check.json`, for this tree's digest). The landing gate guarantees exactness; `make check` re-verifies. The ledger is an operational log and is never read for credit.
11. Locks, all kernel `flock`, each justified, always taken in the order `land`, then `structure`, with `journal.lock` innermost: `store.exclusive("land")` (one drain or data batch at a time, never waited on: a drain that finds it held returns `running: true`; the write itself is serialised by `journal.lock`, so measuring takes no lock), `structure` (renames of paths and members:  and `repo.setup` take it exclusive and wait at most `host.move_wait_s` before refusing `setup.busy`; a drain takes it shared once per entry, once per fuzzy chunk and once around its generate, and a data batch shared for its run, so a move or setup lands between two entries of a running drain instead of excluding the drain), `structure.gate` (a writer waiting with a deadline holds it exclusive, and readers pass it shared before asking for `structure`, so arriving readers queue behind the waiting writer and cannot starve it), `store.slots` (host-wide native concurrency equals `host.workers` across all processes; blocking acquire is the signal), no cache lock (a miss produces unlocked and stores atomically, so production may fan out to the pool). There are no per-group claims.

## Layout is the source tree (schema 4)

`config.toml` is flat at schema 4 (name, toolchain, optional title, names_from, libraries, cppflags, cflags, asflags,
one `[version.<id>]` table per ROM, optional `[file."path or dir/"]` rows). There is no layout.toml, boards.toml,
types.toml or version_differences. A file owns the names it defines or keeps behind `INCLUDE_ASM(SEG, NAME)`,
`INCLUDE_DATA`, `INCLUDE_RODATA` and `INCLUDE_BSS(SEG, NAME, SIZE)`; `tree.capture(config, overlay)` reads it and
`Tree.owner(version, name)` answers who owns a name. Fuzzy C sits in `#ifdef NON_MATCHING`; a per-version difference sits
in `#if VERSION_X`. The commands are `init`, `setup [--no-make]`, `sync [--check|--settle] [--place FUNCTION]...`, `check`, `audit`, `cheat --against REV [--head REV]`, `compare`, `score`, `probe`, `submit`,
`land`, `report`, `map`, `symbols` and `names`. `whatif FILE --function FN [--dep A>B ...|--kind top-priority --insn UID ...] [--search singles|pairs]` compiles the candidate with extra scheduler dependences (or the single-set top priority off) made in cc1 under batch gdb, by symbol name, and scores it like probe; the search reports the smallest exact change set, or what it tried (`exhausted`) and `impossible`. CI is `ci/run` (forge-neutral, the repository's own `make check CHECK=tree` only: a game repository never installs or calls unbake) with thin GitHub and GitLab wrappers. Policy keeps
the source rules and the `unclean` pool, and adds a header lint: each `extern` is declared at most once across `include/`
and a name has the same declaration everywhere (cached in the `header.names` kind by header text).

Symbols: `versions/<v>/symbol_addrs.txt` (splat format, one line per symbol with `type:func|data rom:0x… size:0x…`) is the hand-kept fact file of a version; `unbake sync` appends a stand-in line for every symbol no file owns.

Blobs: `blobs.toml` at the project root (schema 1) is the hand-kept fact file of the ROM content that is neither code nor data: one `[blob."<id>"]` per graphics, model, audio, world or text item with its type, state (`decoded`, `identified`, `observed`), per-version physical `rom` ranges, a `parent` plus `decoded` offsets when it lives inside a compressed stream, and evidence cited by sha256. It stores no bytes. Only `blobs.apply_import` and the explicit `blobs migrate` cutover write it. Every ROM byte is classified once, in this precedence: code, data, platform (`rom.toml [platform]`, a platform fact), decoded blobs, identified blobs, proven fill, unknown. Proven fill (owner decision B1) is computed from the ROM, never hand-kept: an unknown gap read as its one-value runs from its end backwards, a run being padding when its length is below the alignment of its end and that end is the gap's end or the start of the padding run after it (a run inside a longer gap is at least 16 bytes), or when it reaches the ROM end from a 16-byte boundary (`unbake blobs land PACKET` imports a facts-only packet checked and all-or-nothing, with no ROM build); it counts as matched blob bytes (inside `blobs_decoded`, alone in `blobs_fill`). `observed` blobs count in the census but their bytes stay unknown. `code + data + platform + blobs + unknown = rom_size` per version is the blocking check `report.partition`, and `unbake report` carries `rom_size`, `platform_total`, `blobs_total`, `blobs_decoded`, `blobs_identified`, `unknown_total` and a `blobs` census per version. `data` keeps its conventional name (with `INCLUDE_DATA`/`INCLUDE_RODATA`).

Tracked generated files (`unbake sync`; each starts with the stamp `generated from config.toml; do not edit`, and no generated file names a tool: the repo builds with make alone): `Makefile`, `<name>.ld`, `versions/<v>/splat.yaml`, `include/include_asm.h` (absent only), the CI files; the README progress block between `repo.toml readme.begin/end` is written by `unbake report`. ## Published progress

`unbake report` atomically writes `progress.json`, schema 2, and the map files, from its credit rows and checked ROM
partition.
`carts` contains every version: cartridge `id`, `version`, `rom_size`, then its parts `code`, `data` (each `matched`,
`total`), `blobs` (`decoded`, `total`) and `header`: the header block's `bytes` (the platform bytes: cartridge header
and boot code) and the parsed fields of the ROM's 64-byte cartridge header (`pi` `release`/`page_size`/`pulse_width`/
`latency`, `clock_rate`, `entry_point`, libultra `release`, `crc1`, `crc2`, `name`, `game_id`, `country`, `version`),
never raw bytes and nothing past 0x40; and `functions` (`matched`, `total`). There is no fuzzy credit, no blob type
census and no unknown field: what the parts do not cover is the rest of `rom_size`, never stored.
progress.json carries no map. Each version's map is its own file `docs/map-<version>.json` (schema 1, written with
progress.json under the same hold): `version`, `rom_size`, `fns` rows `[name, rom, size, percent, path, line]`,
`blobs` rows `[id, rom, size, state, type]` of the live content types only (accounting rows stay in blobs.toml), and `spans` with `data`, `platform` and `fill` (proven fill) half-open
ranges.
A function without a C definition has null path/line. Zero-byte aliases are excluded. Observed blobs remain unknown.
`report --next` adds `next` rows (`name`, `version`, `size`, `percent`, `path`, `state`), sorted by size, name, version.
`report --exact V ...` also rewrites the README progress block and the overview image from the same rows (`report.files`); `report --states [--exact V ...]` builds nothing and scores nothing: from the source alone it writes `.unbake/states.json` and returns, per version, `functions`/`code` bytes as `exact` (C the ROM build uses, or a stand-in whose assembly carries the handwritten marker), `fuzzy` (a NON_MATCHING body) or `none`, `data` as exact or none, the `none_fns` rows and the split `fragments` (pieces of a function a symbol cut, counted in their parent's state, not as functions) and `asm_missing` (stand-ins whose assembly is not extracted, so they could not be checked for either). Versions not named by `--exact` are taken as linking exact (`exact_from: assumed`); the integration train checks each push.
Queue `state` describes measured credit: `fuzzy` for a positive score, otherwise `unmatched`, using the same
predicate as `functions_fuzzy`. It does not describe source form: a NON_MATCHING C body scoring zero remains
unmatched. Source-body state stays internal for map links, including zero-scoring C bodies.
A NON_MATCHING body remains unmatched even at 100 percent until landed. No schema-1 reader or alternate metric is kept.

`make check` builds every ROM and checks each SHA-1; it never calls unbake. Whoever runs it for credit calls
`unbake verify STATUS` after it with make's exit, including on build failure (`unbake setup`/`check` record the verdict
themselves; `decomp land` calls verify after its check build). Verify needs no host
config: it checks size/SHA-1 against config.toml and records `exact`, `failing`, `build_inputs` in `.unbake/check.json`.
The report grants that verdict only while all build inputs and outputs retain their identity. Source debt keeps its
own tree digest in that same document. A failed build clears exact credit; a missing or corrupt ROM cannot pass.

The README block is not progress.json's shape: the `all` and per-version ROM bars (matched code, data, blobs and
platform, reaching over fuzzy code and identified blobs, `(~x%)` when the reach differs), then per version its
code, data, functions and blobs rows. Bars are █ matched, ▒ fuzzy reach, ░ the rest.
The README blobs bar uses `blobs_total + unknown_total` as its denominator: the ROM bytes outside code, data and
platform. Decoded bytes fill the solid part, identified bytes fill the shaded part, and unknown bytes stay empty.
The README dependencies block is one bullet per build tool the Makefile fetches: `- [name](repository)` from the
tool's `dependency` row (toolchains.toml, repo.toml make.tools), its short name and source repository, never a
download or binary link and no bracket text; a fetched tool without that row refuses as `repo.dependency`.


## Blob types and platform cutover

The only live blob types are `graphics`, `model`, `audio`, `world`, `text`; schemas for both blobs.toml and import
packets reject retired types. There is no catch-all type. Unclassified ranges stay unknown. Microcode is platform
content, never a blob. The report exposes `platform_total`; progress.json schema 2 shows it as the cart
`header.bytes` (the header block) and the map files as `spans.platform`. The former boot report fields are rejected, with no alias. Consumers must change together.

The packaged `rom.toml [platform]` defines `boot = [[0, 4096]]`. A project may add its own `rom.toml`:

```toml
schema = 1
[platform]
boot = [[0, 4096]]
[platform.rsp.sdk_code]
format = "microcode: reviewed SDK binary"
state = "identified"
rom.us = [[32768, 33024]]
sha256.us = ["<SHA-256 of exactly those 256 bytes>"]
```

Boot remains the packaged range; each RSP span needs one exact SHA-256 in the same version/order. A wrong hash,
unknown version or invalid range refuses before credit. This is a declaration of an identified SDK binary, not a
heuristic that treats arbitrary bytes as microcode. Its format/name/evidence retain the identity evidence.

`unbake blobs migrate` is the explicit one-time, journaled migration. It maps texture/sprite/font/layout to graphics,
sound/sequence to audio, level to world, strings/messages to text, and keeps model. The old type is prefixed to
format unless format already names it. Reviewed physical microcode rows move into project rom.toml beside boot,
with exact hashes of their ranges; their metadata/evidence survive. Observed or compressed-only microcode and
unclassifiable/catch-all rows refuse with names for review, without writes. Classify them or remove their declarations
to leave the ranges unknown, then rerun. Normal readers never accept those legacy types.

Before writing, the migration validates both proposed files and compares the exact union of known ROM ranges
(platform plus decoded/identified blobs) per version. The journal pins both input files and writes atomically. It
then rereads both files, rechecks hashes and requires identical ranges and per-version byte totals. Moving microcode
changes its layer from blobs to platform, while known coverage, unknown bytes and total ROM accounting stay fixed.
Comments of retained TOML tables and every metadata field are preserved; the command is idempotent.

Library assembly: setup/sync extracts foreign ROM routines owned under project.libraries into clean .s source units. The pre-cutover renderer is retained; one routine is one `.s` for every version, the lines the versions disagree on in `.if VERSION_*` blocks, and copies the symbol files name apart per version (`func_X_de`, `func_Y_eu`) share one file named without the version suffix when their code has the same shape (a real name wins over `func_<address>`); a routine that cannot render stays a stand-in in a library file (a library routine that lost its stand-in is rendered again, or gets it back at the end of the nearest library file, never in a game file). RNC streams: methods 1 and 2 share bounded header and CRC validation. Method 2 reads MSB-first interleaved tokens, validates overlap distances, raw runs and end markers, and rejects protected streams. `blobs scan` reports `rnc` validation counts and each candidate codec; graph proofs require the declared method to equal the header. A successful decode alone never grants typed data credit.

`blobs prove` reader `rnc-copy` checks two complete method-1/2 streams, both CRCs, equal decoded size and bytes, source-version membership and nonoverlap. The source range must be covered by the named decoded blob; an observed owner or decompression alone is insufficient. Receipts retain both codecs, source extent/hash and the common decoded hash.

`blobs prove` reader `sn-head` proves the first bytes of an SN debug stream (at most 255) as the end of the record a 4 KiB write cut from the stream before it: the bytes before the head are zeros or another write, so the record is proven whole by a witness holding the same bytes and the same following whole record inside a whole record that re-encodes to its source bytes, in the row's ROM or another version's (the receipt names `source_version` and `source`). Identical text alone, with no valid containing record, proves nothing. `copy` finds and proves copies of at least 32 bytes.
`sn-head` reads both dialects (`sym`, then `obj` for an object file's records; the receipt names `dialect` when it is `obj`). `blobs prove` reader `rnc-repack` proves packed bytes of a method 2 RNC stream that later writes damaged (the packed CRC fails, so `rnc` cannot prove it): the bits are decoded as far as they decode, packed again by `rnc2enc` (the deterministic packer, which reproduces all 32 whole method 2 streams of the German ROM byte for byte) and the credited bytes are those before the first byte the packer's output differs, minus the decoded tail a token's choice looked at; the receipt names the decoded size and sha256, the packer settings and the first difference. `blobs prove` names every bad row of a request in one refusal, and a receipt path may be rewritten by the request it answers (another request's receipt is refused). `report --unknown` writes `.unbake/unknown.json`: per version the ROM spans no class holds, `[low, high, size, segment]`. `report` carries a non-blocking `report.size-conflict` note for a symbol name that symbol_addrs.txt and aliases.txt give different sizes.

Typed graphs accept `tagged` streams whose project layout declares a byte terminator, alignment, and cases (`mask`, `value`, scalar record `type`). Each encountered tag must select exactly one record; the first field is its tag byte. Every record re-emits exactly, the terminator is mandatory, and only bounded zero alignment may follow. No game opcodes or layout facts live in the reader.

`blobs prove` reader `c-string` accepts a project-evidenced, explicitly supplied nonempty ASCII C string initializer (`text`). Embedded NUL, control bytes, non-ASCII, missing termination and trailing bytes refuse. Code segments may declare `address_space` (default `main`) with an explicit VMA. A distinct image has its own Splat symbol namespace; its ELF section is INFO, relocated at that VMA without loading into the main image. The generated ROM objcopy rule restores its load flags and declared LMA. Generated assertions bound **every** physical section by the next ROM boundary and reject VMA overlaps within each non-main address space (including BSS). Main image linker checks remain enabled. Separate spaces require code, never bin segments, and globally unique symbol names; no physical bytes are shared or omitted.
