## Invariants

1. A `Refusal` always carries at least one `Finding`; every `Finding.key` is a key of `resources/data/keys.toml`.
2. `Finding.blocking=False` marks project debt. Debt never raises; it is returned and counted.
3. A `Proof` with `exact=False` has nonempty `missing` and `score < 1.0`; `exact=True` has `score == 1.0` and `symptoms == {}`. `land.not_exact` findings copy the `missing` strings and merge the proofs' symptoms.
4. Config values have no defaults. A missing or unknown key refuses with `config.schema` naming `file:dotted.path`. `"auto"` is an explicit host value for `resources.cores`/`resources.workers`; config resolves it to `len(os.sched_getaffinity(0))` and records `Origin.note = "auto: os.sched_getaffinity -> N"`. One exception: `resources.move_wait_s` is optional and reads 600 when absent, so existing host files keep loading.
Host tools used only by particular phases/commands are optional (`cpp`, `mips_as`, `mips_ld`, `mips_objcopy`, `mips_objdump`, `n64link`, `armips`). Config validates every supplied path as executable. A phase needing an omitted tool refuses with `native.missing_tool`, naming the tool and unit kind; no PATH fallback. Migration writes only supplied tools.

5. Every cache key is `contracts.digest(...)` of content (bytes digests, recipe digest, tool pins), never mtimes or reprs. A key that guards a producer holds `code_identity(producer)`, never a source file.
6. Unbake never writes Git state: no commit, no staging, no reset (read-only `rev-parse`, `ls-files`, `diff`, `show`, `log` only). Only `journal.apply` writes tracked project files, into the working tree, and only `land.drain`, `move.run`, `batch_data` and `repo.setup` call it, `repo.setup` and `move.run` while they hold `store.exclusive(config, "structure")`, `batch_data` while it holds `store.exclusive(config, "land")` and then `store.shared(config, "structure")`, `land.drain` per claimed entry under `store.shared(config, "structure")` with the write alone serialised by `journal.lock`. `apply` stages every new content beside its target before taking `journal.lock`, then renames them all into place under it, and `layout.capture` reads under the shared side of that lock, so a capture sees the old file set or the new one. `apply` refuses a path whose current bytes differ from what the snapshot read (`Snapshot.reads`, seeded by the capture pins), journals the old bytes of every path (or absent) before writing, and returns the written paths for the caller to commit; the human output prints the exact `git add` and one-line `git commit -m`. Every other writer writes only untracked runtime files under `<project>/.unbake/` (inbox, ledger, stages, check.json), `local.mk`, view's content-keyed `build/views/<digest>/` materialisation (kept from revision 3), or the host cache, each by atomic create/rename or `O_APPEND`.
7. Only process.py starts processes, only pool.py creates worker processes, only effort.py, process.py and pool.py read rusage. Lint greps imports of `subprocess`, `multiprocessing`, `concurrent.futures`, `threading`, `os.fork`.
8. `view.all_versions` returns exactly the requested version keys.
9. Toolchain, assembler, linker, unit-kind and repository-file behaviour comes from resources; the strings `"gcc"`, `"ido"`, `"c"`, `"asm"`, `"data"`, `"resource"` appear only in resources and tests (lint).
10. Credit is state, not history: a member is matched in a version iff it belongs to a layout unit whose kind has `decompiled = true` and holds that version. The landing gate guarantees exactness; `make check` re-verifies. The ledger is an operational log and is never read for credit.
11. Locks, all kernel `flock`, each justified, always taken in the order `land`, then `structure`, with `journal.lock` innermost: `store.exclusive("land")` (one drain or data batch at a time, never waited on: a drain that finds it held returns `running: true`; the write itself is serialised by `journal.lock`, so measuring takes no lock), `structure` (renames of paths and members: `move.run` and `repo.setup` take it exclusive and wait at most `host.move_wait_s` before refusing `setup.busy`; a drain takes it shared once per entry, once per fuzzy chunk and once around its generate, and a data batch shared for its run, so a move or setup lands between two entries of a running drain instead of excluding the drain), `structure.gate` (a writer waiting with a deadline holds it exclusive, and readers pass it shared before asking for `structure`, so arriving readers queue behind the waiting writer and cannot starve it), `store.slots` (host-wide native concurrency equals `host.workers` across all processes; blocking acquire is the signal), no cache lock (a miss produces unlocked and stores atomically, so production may fan out to the pool). There are no per-group claims.

## Shapes shared between modules

Inferred modules (`infer.groups`): authored and proven modules stay. Every other function run is cut by evidence (shared rodata, shared callees, version holders, padded object boundaries, the `repo.toml [layout] module_cap`) and always at a toolchain change between two landed units and at an sdk edge, so a module never holds sdk and game code. `layout.subsystems` places modules (`unbake map --moves`) in `src/sdk/<library>` and `src/game/[<segment>/]<subsystem>`: a producer for new games and for lanes after a freeze, not part of a frozen cutover replay.

- `request` (admission) = `{"file": str, "function": str | None, "overrides": {"toolchain"?: str, "add": [str], "omit": [str]}, "note": str}`.
- CLI `params` = the click parameter dict with the names declared in `commands.toml` (`-` becomes `_`).
- Every CLI result validates against `schemas/result.<command>.schema.json` (`report --next` against `result.next`); the stdout line validates against `envelope`.
- DRAIN (`result.land`, embedded in submit/compare/check results) = `{running, landed: [{id, member, operation, files, message}], refused: [{id, member, findings}]}`.
- Built bytes: `native.measure` stores each proof's built material (sections in placement order) with `store.put(config, "bytes", proof.built_sha256, material)`; readers fetch it with `store.cached(config, "bytes", sha, produce)` where `produce` raises `Refusal(Finding("store.corrupt", ...))`.
- effort events passed to `listen` callbacks: `("open", {"path": [str]})`, `("close", {"path": [str], "wall": float, "status": str})`, `("progress", {"name": str, "done": int, "total": int})`, `("say", {"text": str})`.

Project library_dirs names source subdirectories containing vendored library code. Policy and declaration folding leave their original idioms intact; every compiled unit still requires exact ROM proofs. version_differences entries name a function and its sides, the holding versions partitioned by the branches of one #if/#elif/#else chain (two or more sides). Guard lines are accepted only when their branches are whole sides under the macro configuration, the target bytes differ between sides, and the candidate proves exact in every holder. `check --repair` rewrites the rows from the guards that pass.

Foreign routines (a function holding a mnemonic in the toolchain's `never_emits`, or `cfc1`/`ctc1` without one of its `fpu_control_with` conversions, in every version holding it) are library assembly: report/queue rows name them kind `library-asm`, `unbake setup` writes them from the ROM bytes into their module's own path with the suffix `.s` (one instruction per line, labels for internal targets, symbol names for external ones, `%hi`/`%lo` of named symbols) when that path is in a library dir, and binds it as an assembly unit that counts as matched code. A module whose routines different versions hold, or that other code splits, gets one `.s` per run of routines the same versions hold contiguously (the first at the module path, the others named by their first routine). Otherwise nothing is written and debt findings `library-asm.unplaced`, `.mixed`, `.unnamed-target` or `.version-split` (one routine whose versions render differently) name the function. Assembly units outside library_dirs are policy debt `source.asm-outside-library`.
